실제 연결 검증: 실행 환경의 `codex login status`가 `Logged in using ChatGPT`임을 확인했습니다. `data/codex-connected-verification.sqlite3`에서 `--ai codex demo --steps 1`을 실행해 `supervisor_ai_plan`을 저장했습니다. Codex는 최초 관측에 거래/성과 이력이 없고 두 마켓의 RSI가 과열되어 있다는 근거로 `actions=[]`인 대기를 선택했습니다. 실제 연결 검증에서는 환경 생성이 발생하지 않았으며, 생성·전략 변경 실행은 통합 테스트에서 검증했습니다. 이 작업의 제한된 파일 시스템에서는 CLI가 사용자 상태 DB를 열 수 없어 연결 실패가 발생했지만, 정상 사용자 환경 접근으로 다시 실행했을 때 성공했습니다.

실거래, 수익성 보장, 봉 내부 연속 손절 추적은 구현 범위가 아닙니다. 생존 평가 대상은 일반 거래 에이전트이며 총괄은 운영자로 유지됩니다. 상세 설정/한계는 [운영 안내](ecosystem.md)에 있습니다.

지갑 유형/토큰 관리 검증을 추가했습니다. 혼합형만 모델에 전달되는지, 규칙에서 신호가 없을 때 생성형 매수를 반영하는지, 투자 비중 상한·보유 상태·강제 손절 보호, 지갑별 호출 간격, 부적합 출력·호출 실패, 실제/알 수 없는 사용량 정산, 일일 호출·토큰 예산 차단, 날짜 갱신, 재시작 지속과 틱 롤백 후 판단 재사용을 확인했습니다.

PATH의 CLI 0.135.0은 최신 모델 카탈로그를 읽지 못하고 `gpt-6-luna`를 거절했습니다. 공식 CLI 0.162.1을 프로젝트 `data/codex-runtime`에 설치한 뒤 기존 ChatGPT 로그인을 상속해 `data/worker-latest-verification.sqlite3`에서 총괄과 혼합형의 실제 판단을 모두 확인했습니다. 작업 중 사용자 전역 CLI 설치는 바꾸지 않았습니다.

거래 판단 전용 지시문과 도구 비활성화를 적용한 실제 실행 `data/worker-compact-verification.sqlite3`는 총괄 계획 1회, 경량 거래 검토 1회를 저장했습니다. 경량 모델은 대기 판단을 반환했고 실제 사용량은 입력 7,455 + 출력 57 = **7,512토큰**입니다. 앞선 기본 CLI 지시문을 사용한 검토는 15,393토큰으로, 같은 첫 틱에서 약 51% 줄었습니다. 두 번의 검증에서 생성형 신호에 의한 실제 매수는 발생하지 않았으며 매수 반영은 통합 테스트로 검증했습니다. 이 수치는 한 지갑·한 회차의 관측으로 이후 소비를 보장하지 않습니다.
