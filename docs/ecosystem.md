# 진화형 가상매매 에이전트

거래 에이전트는 SQLite에 저장된 별도 지갑과 전략 유전자를 가지고 KRW 현물 가상매매를 수행합니다. 기본 규칙 기반(`rules`)과 생성형 AI 기반(`hybrid`, 규칙과 모델 판단 결합)의 두 종류입니다. 총괄 에이전트는 지갑 없이 거래 에이전트를 관리하고 전략을 개선합니다. 격리 환경은 거래 에이전트가 생존 평가·교배·돌연변이에 따라 진화하는 환경으로, 주요 환경(`main`) 외에 총괄 판단으로 부속 환경을 만들어 테스트할 수 있습니다. 라이브의 총괄 판단은 로그인된 Codex CLI로 실행하고 데모는 기본적으로 오프라인 규칙 모드입니다.

## 전략과 지갑

```powershell
python -m coin.agents demo --steps 60
python -m coin.agents --db data/demo-agents.sqlite3 status
python -m coin.agents run
python -m coin.agents events --limit 50
```

`run`은 Ctrl+C까지 계속 실행합니다. `run --steps 2`는 수집을 두 번 시도하며 새로운 완료 봉이 없으면 처리 틱 수는 늘지 않습니다. 옵션 `--db`와 `--config`는 하위 명령 앞에 지정합니다. 데모는 같은 시드와 설정으로 이어서 실행합니다.

초기 전략은 이동평균·RSI 기반 추세, 볼린저밴드·RSI 기반 평균회귀, 직전 완료 봉의 고가 채널·거래량 기반 돌파입니다. 에이전트별 매수 비중, 손절, 익절, RSI 문턱, 돌파 기간 등은 독립된 유전자입니다. 보유 포지션에는 추가 매수하지 않으며 원가 기준 손절·익절을 먼저 판단합니다. 오래되거나 지표가 부족한 차트에서는 진입을 보류합니다.

매수는 수수료를 포함한 가상 원화 예산을 사용하며 매도는 보유 코인 수량을 사용합니다. 지갑 간 잔고를 공유하지 않습니다. `agents.toml`의 `fee_rate=0.0004`, `min_notional=5000`은 시뮬레이션 가정입니다.

## 생존과 진화

`survival` 설정에 따라 거래 에이전트의 최대 낙폭, 초기 자본 대비 평가액 하한, 유예 기간 후 수익률과 매수 후 보유 벤치마크 대비 성과, 최소 거래 횟수를 평가합니다. 총괄은 거래 개체군 밖의 운영자이므로 거래·개체 나이·수익률·생존 평가 대상이 아닙니다. `tick`은 처리된 새로운 완료 봉 입력 횟수이며 30초 폴링 횟수와 다릅니다. 개체 나이는 자신의 마켓에 새로운 완료 봉이 들어온 경우에만 증가합니다. 이미 처리한 입력을 다시 수집하면 매매·진화를 반복하지 않습니다.

기본값은 최대 낙폭 15%, 자본 하한 75%, 유예 48틱, 24틱마다 최소 수익률 -2%와 벤치마크 초과 수익률 -6%, 96틱까지 최소 거래 1회입니다. 거래 실패나 시세 수집 오류는 기록됩니다.

사망 에이전트는 거래를 중단합니다. 보유분을 현재 매수호가에 가상 청산하고 가용 현금을 해당 환경의 금고로 회수합니다. 잔량이나 최소 거래금액 때문에 청산할 수 없는 포지션은 사망 지갑에 동결해 기록하며 새 에이전트의 자본으로 사용하지 않습니다.

진화는 환경 안에서 부모 전략의 유전자를 교배하고 제한 범위 안에서 돌연변이를 적용합니다. 부모는 `min_parent_age` 이상 관측한 개체에서 우선 선택하며 벤치마크 초과 수익률·최대 낙폭·관측 나이를 반영한 점수를 사용합니다. 생존 개체를 우선하고 모두 사망한 경우 기록된 부모 전략을 활용합니다. 적격 부모가 없으면 기본 전략으로 다시 탐색합니다. 새 자녀는 부모와 별도 지갑·전략을 갖고, 부모 ID와 세대를 기록합니다. `seed`를 고정하면 동일한 입력과 상태에서 유전자 선택을 재현할 수 있습니다. 새 에이전트는 환경 금고에 충분한 자본이 있고 최대 개체 수를 넘지 않을 때만 생성됩니다.

## 총괄과 격리 환경

거래 지갑의 `decision_mode`는 `rules` 또는 `hybrid`입니다. `rules`는 유전자 전략/AI가 앞서 작성한 조건식을 실행하며 매매마다 모델을 호출하지 않습니다. `hybrid`는 그 규칙 판단에 경량 모델의 현재 매수·매도·대기 판단을 결합합니다. 총괄의 `decision_mode` 선택으로 생성/변경하거나 `python -m coin.agents mode <agent-id> hybrid`로 전환합니다. 기존 DB에 유형 열이 없는 경우 활성 거래 에이전트를 `workers.initial_modes` 구성에 맞춰 이관하며 지갑 잔고와 계보는 유지합니다.

혼합형의 판단은 DB 쓰기 잠금 밖에서 일괄 요청합니다. 이전 호출이 오래된 지갑부터 최대 `workers.max_agents_per_call`개를 선택하고 지갑별 `every_ticks` 간격을 적용합니다. 응답은 요청한 각 지갑의 ID·행동·짧은 근거·투자 비중을 갖고, 누락/중복/알 수 없는 ID를 거절합니다. 프레임 처리 시 현재 계좌 상태와 보호 규칙을 다시 적용합니다. 혼합형 호출 오류나 예산 부족 시 기존 규칙을 사용하고 이벤트로 남깁니다. 강제 손절·익절과 품질 문제가 있는 지갑에는 생성형 검토를 요청하지 않습니다.

`ai_calls`는 총괄/거래 판단별 일일 호출 수와 토큰을 영속 기록합니다. KST 날짜 기준으로 갱신하고, 요청 전에 예약량을 기록하며 CLI가 반환한 실제 입력+출력 토큰으로 정산합니다. 알 수 없는 사용량은 예약량으로 회계 처리합니다. 실패·크래시·틱 롤백 후에도 소비한 호출을 잊지 않으며, 동일 프레임 요청은 기존 결과를 재사용합니다. 소프트 예산으로 한 호출의 실제 소비가 예약량을 초과할 수 있습니다. `status.ai_usage`는 사용량 미확인 회차도 구분합니다. 원장에는 호출 중 상태가 남으므로 중단한 호출을 무조건 재시도하지 않습니다.

가벼운 거래 모델과 낮은 추론 강도는 `[workers]`에서 별도로 설정합니다. 기본 `gpt-6-luna`는 [공식 모델 안내](https://learn.chatgpt.com/docs/models?surface=cli)의 반복적인 작업용 모델입니다. 실제 모델 접근 가능 여부는 실행 CLI·계정·워크스페이스에 따라 달라지며, 오류 시 더 무거운 모델로 자동 전환하지 않습니다. 프로젝트의 `data/codex-runtime/node_modules/.bin/codex` (`Windows: codex.cmd`)가 있으면 기본 명령 `codex`보다 우선합니다.

총괄 에이전트는 거래 에이전트의 성과를 관측하고 더 효율적인 전략을 찾기 위한 생성·수정·실험을 관리합니다. `ai.backend="codex"`에서는 시장 차트·외부 자료·거래 지갑과 성과·사망 상태·최근 이벤트·적용 조건식을 Codex에 전달합니다. 생성형 총괄은 상황에 따라 `create_environment`, `spawn_agent`, `revise_strategy` 행동 또는 대기를 선택합니다. 정해진 시점에 무조건 환경을 만들던 규칙 총괄은 이 모드에서 실행하지 않습니다. 기존 교배·생존 평가는 계속 실행합니다.

AI 계획은 JSON 스키마로 받아 검증하고, 행동별 savepoint에서 실행합니다. 새 환경은 AI가 정한 이름·목적·예산·초기 전략을 가지며, 예비금에서 금고로 자본을 이체하고 독립 지갑 1개를 생성합니다. 같은 계획의 후속 `spawn_agent`로 추가 배치할 수 있습니다. 각 계획의 출생은 `evolution.max_births_per_tick` 이내입니다. 환경 수·환경당 활성 개체 수·예비금·금고·환경 예산 상한을 실행기가 검사합니다. `revise_strategy`는 활성 개체의 유전자와 조건식만 바꾸며 지갑과 계보를 유지합니다. 행동이 거절되면 해당 행동만 롤백하고 이유를 기록합니다.

AI가 작성하는 실행 규칙은 `buy`와 `sell`의 AND 조건 목록입니다. 각 조건은 `left`, `op` (`gt`, `gte`, `lt`, `lte`), `right_field` 또는 `right_value`를 가지며 오른쪽 피연산자는 정확히 하나만 지정합니다. 가격·이동평균·RSI·거래량 비율·볼린저밴드·보유 수익률을 비교할 수 있습니다. 빈 목록은 해당 방향을 실행하지 않습니다. 예를 들어 `price > sma20 AND volume_ratio20 >= 1.4`라는 새 진입 규칙을 AI가 만들 수 있습니다. 조건식은 차트 신호를 대체하지만 손절·익절·차트 품질·심리 자료 문턱·계좌 생존 검사는 유지합니다. `policy=null`로 변경하면 기본 유전자 전략을 사용합니다. AI 조건식은 개체별 저장되며 교배 자녀에게 자동 상속하지 않습니다. 적용된 전략은 다음 틱부터 작동합니다.

`coin/generative.py`는 실행 사용자 환경과 `CODEX_HOME`을 상속한 `codex exec`를 호출합니다. 기존 ChatGPT 로그인만 사용하고 API 키 환경 변수는 제외합니다. `--output-schema`, `--output-last-message`, `--ephemeral`, `--sandbox read-only`, `--ignore-user-config`로 구조화된 판단을 받으며 사용자 설정의 임의 MCP/훅을 불러오지 않습니다. 모델을 지정하지 않으면 CLI 기본 모델을 사용합니다. 공식 근거: [비대화형 실행](https://learn.chatgpt.com/docs/non-interactive-mode), [Codex 인증](https://learn.chatgpt.com/docs/auth).

CLI 호출은 DB 쓰기 잠금 밖에서 수행하고, 판단 중 처리 틱이 바뀌면 오래된 계획을 폐기합니다. 오류 시 규칙 총괄로 전환하지 않고 `supervisor_ai_error`를 남겨 해당 회차의 총괄 행동을 생략합니다. 일반 전략은 계속 작동합니다. CLI 요청에는 시장 자료와 가상 지갑 상태가 전송됩니다. 판단에 시간이 걸려도 가상 체결은 수집한 프레임의 호가를 사용하므로 이 결과는 실시간 주문 지연을 모델링하지 않습니다.

기본 주요 격리 환경 예산은 가상 100만 원입니다. 초기 거래 에이전트 3개에 각각 10만 원을 배정하고 70만 원은 환경 금고에 남습니다. 실험 예비금 100만 원은 별도로 확보합니다. 부속 환경은 예비금에서 40만 원을 이체하고 환경 수는 주요 환경을 포함해 최대 3개입니다. 금고와 예비금은 시스템 자금이며 총괄 지갑이 아닙니다.

`status.supervisor`는 지갑 없는 관리자를 표시하고 `status.agents`에는 거래 에이전트만 표시합니다. 기존 `supervisor.cash` 설정은 호환성을 위해 무시합니다. 기존 DB를 열면 과거 총괄 계좌의 현금을 해당 환경 금고로 반환하고 거래를 중단합니다. 보유 포지션과 거래 이력은 `status.archived_accounts`에 보존하며 자본 회계에 계속 포함합니다. 과거 계좌는 거래·생존·교배에서 제외됩니다. 전환은 트랜잭션으로 한 번만 수행하고 `supervisor_wallet_archived` 이벤트에 기록합니다.

## 외부 정보와 기록

`system.external=true`로 뉴스·심리지수를 주기적으로 수집할 수 있습니다. 뉴스 제목은 분석 근거로 저장하며 자동 매수 지시로 해석하지 않습니다. 전략 유전자의 `sentiment_min`이 0보다 크면 최근 심리지수 증거가 문턱을 충족해야 진입합니다. 기본 전략은 이 조건을 비활성화합니다. 설정과 직접 조사 자료 연결 방법은 [분석 환경](analysis.md)을 참고하세요.

지갑, 거래, 전략, 부모·세대, 성과, 사망, 출생, 환경 생성, 총괄 관측과 원본 시세 입력을 저장합니다. 한 틱의 변경은 같은 데이터베이스 트랜잭션으로 커밋됩니다. 동일 데이터베이스는 같은 설정으로 재시작하고 설정 변경 실험에는 새 데이터베이스를 사용하세요.

`status`의 `capital_accounting`은 예비금·환경 금고·지갑 현금·포지션 원가를 합산하여 `초기 총자본 + 누적 실현 손익`과 비교합니다. `identity_error`가 0에 가까워야 자본 배정/회수 과정에 자금 생성이나 누락이 없다는 뜻입니다. 사망 시 `terminal_equity`는 회수 전 평가액 기록이며 회수된 현금과 중복 합산하지 않습니다. 이 회계 점검은 시세 평가 손익과 별개입니다.

## 시뮬레이션 범위

라이브 모드는 빗썸 공개 API의 현재 시세를 이용한 가상매매입니다. 데모 모드는 생성한 가격 경로를 사용하여 생존·진화·총괄 기능을 빠르게 확인하는 실행입니다. 두 입력은 별도 데이터베이스를 사용합니다. 데모 수익률은 실제 시장에서의 수익성 증거가 아닙니다.

한 에이전트는 배정된 한 마켓을 거래합니다. 완료 봉 주기로 판단하므로 봉 내부에서 발생하는 급락과 손절을 연속 추적하는 구조는 아닙니다. 호가의 여러 가격대를 사용하지만 주문 지연, 시장 충격, 주문 대기열, 부분 체결, 지정가 주문은 모델링하지 않습니다. 에이전트들의 가상 체결은 호가 잔량을 서로 차감하지 않습니다. 실거래 주문·출금 기능은 없습니다.
